# 工作台逻辑检查

本次检查覆盖网站设置、社交链接、背景来源、首页区块和评论管理之间的数据流。以下记录描述当前实现，不代表所有可能的配置和第三方服务都已经验证。

## 已修复

- 社交账号、网站和站内媒体路径使用统一的地址校验；不能保存无效地址或协议。用户显式添加的可见链接不会因为与背景地址或其他社交链接重复而被传送门隐藏；页脚显示所有可见社交链接，媒体二维码会作为图片打开。
- 导航和社交链接按界面显示的顺序保存，即使数据库中的原始排序编号不连续，新增或调整顺序后也不会错位。
- 外观设置先完成整组校验，再作为一个事务保存，避免某个字段无效时其他字段已被部分保存。
- 背景来源的创建、启用、编辑和删除与当前背景设置作为事务同步；从外观表单直接保存了不同的背景后，旧来源不再显示为“使用中”。切换来源会先提醒有未保存的背景修改。
- 评论状态筛选在数据库中执行，超过一页时也能找到待审核或已通过的评论；审核和删除后刷新当前列表，避免分页位置错乱。
- 首页中间区块的显示顺序与后台排序一致；传送门固定在末屏，仅开启传送门时也有内容可显示。

## 需要了解的规则

- 社交链接支持站内路径、HTTP(S) 和 `mailto:`。QQ、微信二维码可以上传到媒体库并填写媒体路径；不自动生成或打开第三方应用的专有协议。
- 背景来源库的启用、修改和删除是即时保存；外观表单中的其他设置需要点击“保存更改”。
- 访客的明暗主题选择优先于站长设定的默认主题。单独指定背景颜色的首页区块会使用与之对比清晰的文字颜色。
- 草稿支持自动保存；已发布内容的修改应通过工作台的保存/发布操作确认。浏览数是近似统计，评论提交后需要站长审核。
- 首页仍采用预设区块，首屏在最前、传送门合并在末屏、页脚在末尾；尚不支持任意拖放和自定义新区块类型。
- GitHub 动态和外部背景依赖对应的第三方服务。内容、上传媒体、评论和账号保存在 PostgreSQL，部署和迁移前应备份数据库。
